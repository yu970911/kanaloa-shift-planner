# ホテルかなろあ シフト自動作成

希望休と予約客室数から、月次のシフト案を自動で作るツールです。
ブラウザだけで動きます（サーバー・ビルド不要、データは端末の localStorage に保存）。
ログインすると、クラウド保存・複数パソコンでの共有・過去の生成例の閲覧や「元に戻す」も使えます（後述）。

## ログイン・クラウド保存・履歴（任意）

画面右上の「ログイン」から、メールアドレスとパスワードでアカウントを作れます。
ログインすると以下が使えるようになります（ログインしなくても、今までどおりファイル保存だけで使えます）。

- **クラウド保存（自動）**: 入力して数秒たつと、今の状態（希望休・客室数・名簿・組んだシフト）が自動でクラウドに保存されます。別のパソコンからログインすれば同じ状態を読み込めます。画面上部に「クラウドに保存 HH:MM」と出ます。
- **ほかのパソコンとの衝突防止**: 別のパソコンが先に新しい内容を保存していた場合は、気づかず上書きしないよう確認が出ます（「読み込む」でも「上書き」でも、置き換わる側の内容は履歴に残ります）。
- **履歴（過去のAIシフト生成例）**: 履歴は30分に1回と、「クラウドに保存」ボタンを押したときに1件残ります（入力のたびには増えません）。過去の保存内容を一覧から選んで確認できます。
- **元に戻す**: 履歴から選んだ内容を「今の状態」に戻せます。戻す操作自体も履歴に残るので、間違えてもやり直せます。

裏側は Vercel Functions + Vercel Blob（`/api/*`）で、このリポジトリと同じ Vercel プロジェクトにデプロイされています。
パスワードは PBKDF2 でハッシュ化して保存し、平文は保存しません。セッションはランダムなトークンを Cookie に入れる方式で、
本人のデータだけが `data/<メールのハッシュ>/...` の下に保存されます（メールアドレスそのものは保存キーに使いません）。

GitHub Pages 版（`https://<user>.github.io/kanaloa-shift-planner/`）と Vercel 版とではログイン機能の有無が異なる場合があります。
クラウド機能を使う場合は、`/api` が動く Vercel のURL（例: `https://shift-planner-omega.vercel.app/`）から開いてください。

## ほかのパソコンで使う

「詳細設定 → スプレッドシート連携」を設定したあと、「設定リンクをコピー」を押すと
`https://…/#setup=…` の形のリンクができます。ほかのパソコンでそのリンクを開くと、
ウェブアプリのURLと合言葉が自動で入り、そのまま最新のデータを読み込めます。
リンクには合言葉が入っているので、社内だけで共有してください。

## データの保存

入力するたび、そのブラウザに自動で保存されます（別のパソコンには引き継がれません）。
別のパソコンに移すときや、消えると困るときは、上のバーの「ファイルに保存」でファイルに書き出し、
移した先で「ファイルから戻す」を押してください。希望休・予約客室数・名簿・組んだシフトが全部入っています。

## 使い方

```bash
node serve.js      # http://localhost:8787
```

`index.html` を直接開いても動きますが、ES モジュールを使っているため簡易サーバー経由を推奨します。

## 15日ごとに組む（前半・後半）

シフトは **前半（1〜15日）** と **後半（16日〜月末）** に分けて、15日ぶんずつ組みます。
画面の上の「前半」「後半」の札で切り替えます。

- **締切**：期間の開始日の **2日前** までにシフトを完成させて、スタッフに通知します（前半なら 9/29、後半なら 10/14 のように、札に日付を出します）。「日前」の数字は札の右で変えられます。
  締切が近づく（3日前〜）と黄色、過ぎても完成していないと赤で知らせます。
- **完成＝確定**：手順3で手直しが終わったら「このシフトで確定する」を押します。確定すると締切の警告が消え、通知文が使えます。組み直すと確定は取り消されます。
- **後半は前半を引き継ぐ**：前半が組んであれば、後半は前半の結果をそのまま確定として使い、連勤・週の労働時間・月の休日数・月の労働時間の上限を **月全体で** 守ります。前半は1マスも変わりません。
- **前半だけのとき**：休日数と出勤日数の目安は、月の数字を日割りにします（社員の休み月8日 → 前半は4日）。労働時間の上限も、その日数ぶんに日割りです。
- 前半を組み直したときは、後半も組み直してください（前半を引き継いでいるため）。
- スプレッドシートには、組んである期間をまとめて月のシートに書きます（まだの期間は空欄）。

## 画面の流れ

| 手順 | やること |
|---|---|
| ① 希望を集める | 提出状況の確認、希望休の取り込み、予約客室数の入力 |
| ② シフトを組む | 条件を満たす配置を探索（進捗は実際の探索結果を表示） |
| ③ 確認して仕上げる | 手直し、申し送りの確認、確定、スタッフへの通知（LINE用の文面・画像）、共有（スプレッドシート） |

## 希望休の集め方

**Googleフォーム**（おすすめ）と **LINE・メッセージの貼り付け** の両方に対応します。

### Googleフォームで集める

[gas/CreateForm.gs](gas/CreateForm.gs) を実行すると、その月のフォームが自動でできます。
31日分のチェックボックスを手で作る必要はありません。

1. <https://script.google.com> で「新しいプロジェクト」（連携用 Code.gs とは**別のプロジェクト**にする）
2. [gas/CreateForm.gs](gas/CreateForm.gs) を貼り付け
3. 冒頭の `YEAR` `MONTH` `DEADLINE` `STAFF` を直す
4. `createShiftRequestForm` を実行 → 承認 → 実行ログに出た**回答用URL**をスタッフに送る

フォームの質問と、ツール側の読み取りは次のように対応します。

| フォームの質問 | ツールでの扱い |
|---|---|
| お名前（プルダウン） | 名簿と突き合わせ。選択式なので表記ゆれが起きない |
| ◯月の希望休（チェックボックス） | 休（有給にする日は、連絡事項を見てツール上で「特」に変える） |
| 連休の希望（プルダウン） | 連休の希望（日にちは生成時に決定） |
| 連絡事項（記述） | 「10日まで出勤」などの期間は自動で反映。それ以外は取り込み結果に一覧表示（選んだ日の記号は変えない） |

翌月も `MONTH` を変えて実行するだけです。

### LINE・メッセージを貼り付ける

形式を問わず、名前と日にちが入っていれば読み取ります。

| 書き方 | 解釈 |
|---|---|
| `日下 6日12日は休み` | 6日・12日が休み（苗字だけで照合） |
| `10日まで出勤で退社` | 11日〜月末が休み |
| `15日から出勤します` | 1日〜14日が休み |
| `20日以降はお休み` | 20日〜月末が休み |
| `3連休が取りたい` | 日にちは決めず、生成時に3日続けて休みにする |
| `15〜17 有給で` | 15〜17日が特別休暇（特） |
| `どうしても来られません` | 不在・NG（✖） |

読み取れなかった分・同じ苗字が複数いる場合は、勝手に決めずに「確認が必要」として画面に出します。

## スタッフへの通知

手順3の「スタッフに通知する」に、LINEに貼れる文面ができます。

- **全員への連絡**：期間と確認のお願い。「この期間の画像を作る」で、その期間のシフト表を1枚の画像にします（SlackやLINEに貼れます）。
- **個人ごとの勤務予定**：その人の日ごとの勤務と時間、出勤・休みの日数。「全員分をまとめてコピー」もできます。
  ランチの時間帯（H は 10:30〜13:30、D は 11:00〜14:00）は、宮平さん・日下さんは「厨房」、ほかの人は「清掃」と添えます。

送信は、文面と画像をコピーして自分でSlackやLINEに貼ります（自動送信はしません）。

| E | 6:30〜11:00 / 12:00〜15:30 | 1h | 朝食シフト（今は川島さんが朝食をするので枠なし） |

| H | 10:30〜13:30 / 16:30〜21:30 | 3h | ホテルの昼食・夕食。宮平さんは厨房。ほかの人は、昼は部屋の清掃、夜はホール・清掃 |

## 生成のルール

**必要人員（初期値）**

10月の動き（2026-09-28 のシフトMTG・9月後半のシートより）：朝は川島さんが6時から朝食を8時に仕上げ、8時にBの人が来て送迎します。
昼は宮平さんと日下さんが厨房でランチをし、ほかの人は部屋の清掃です。夜は焼き鳥屋（D）が2名、ホテルの夕食は厨房が川島さんと宮平さん、ホールが平日1名・休日2名です。夜のフロントはいません。

| 枠 | 内容 |
|---|---|
| 焼き鳥屋・夕（D） | **2名必須**。**水曜・土曜は休み**（9月のシートと、MTGでの訂正どおり）。日下さんが入る日だけ営業し、日下さんが休みの日は休業（申し送りに出ます）。日下さん以外は、アスナさん → 難しい日は KYI SU さん・EI KAY ZIN HAN さん |
| 清掃・ホール（H） | 平日1名、土・日・祝日は2名（日本の祝日を自動で判定。振替休日も含む）。昼は部屋の清掃、夜はホール・清掃。夜の厨房は川島さん・宮平さん、夜のフロントは置きません |
| ホテル厨房（宮平・H） | 宮平さんだけが入れる（空きでOK。休みの日は川島さん・け子さんで回る） |
| フロント・送迎（B） | 1名（満室の日は客室20室ごとに1名増やして手厚く）。フロントか送迎ができる人（サムパツ・KYI SU・EI KAY ZIN HAN・薄田）。送迎は車の運転ができる人。できない人がBのときは、川島さんが送迎してその人がホール |

**清掃の人数**：昼に清掃をするのは B・H・D のアスナさん（宮平さん・日下さんはランチの厨房）。普段は3名、満室の日は多くて3〜4名です。
特定の日だけ増やしたいときは、予約客室数の欄の「清掃」に**合計人数**を入れます（例：10/2 は4名）。足りない分は、清掃・ホール（H）を増やします。

島村さん・け子さんなど、シフトに決まって入らない人は枠の人数に数えません。島村さんは風邪で9/30まで休みのため、10月前半は空白（手入力のみ）にしています。戻ったら、スタッフ表の割当モードを「常勤（記号なし）」に戻してください。

**予約客室数の入れ方**：ねっぱん（サイトコントローラー）の残室数を貼ると、予約客室数＝全客室数（28）−残室数で入ります（「貼り付けから取り込む」の横のチェックで切り替え。全客室数は同じカードで変えられます）。
貼れる形は、数字を1日目から並べたもの、または1行1日の「10/1 14」「10月1日(木) 14」「2026/10/1,14」など。見出しの行や別の月の行は読み飛ばします。
日付のない数字の並びとして読んだときは、ずれていないか確認が出ます。

**リクエスト（日ごとの指示）**：「リクエスト」のカードに文章で書くと、その日の設定に反映されます。
- 「13日は超多忙なので全員出勤」「9、10、11日はお祭りなので全員出勤」「16〜18日は全員出勤」 → 全員出勤の日（理由はその日のメモに残ります）
- 「2日は清掃4人」 → 清掃の合計人数　／　「13日は満室」「12日は20室」 → 予約客室数　／　「7日は休館」 → 休館
- 「20日は焼き鳥屋は休み」「25日はホールを3人」 → その枠の人数
- 1行に何件でも書けます（読点・空白・改行・句点で区切る）。日にちは「13日」「10/13」「9、10、11日」「16日から18日」「16〜18日」（全角の「～」も可）。
- 読み取れなかった指示（日にちだけ・何をするか不明・「全員出勤ではない」のような否定など）は、勝手に決めず「読み取れませんでした」に出します。
- 個人の希望休（「宮平 13日は休み」）は、上の「希望休を取り込む」に入れます。「サム 10/15〜11/15休」のような月をまたぐ書き方も読めます。
- 反映した内容は、予約客室数の欄（黄色の日が全員出勤）でいつでも直せます。「日ごとの指示を全部消す」で、この月の指示だけをまとめて消せます。

**全員出勤の日**：超多忙の日は、予約客室数の欄の「全員出勤」にチェックを入れます（2026年10月は 9・10・11日と 16・17・18日）。
枠が埋まったあとも、入れる人はみんな入ります。希望休・連勤（6日まで）・労働時間の上限は守るため、その手前で休みを先に取ってもらいます。
それでも休みになる人がいる日は、申し送りに出ます。

**人が足りないとき**：必須の枠の合計が、出勤できる人数（労働時間の上限・月8日の休み）を超えると、「人が足りない枠」として申し送りに出ます。
自動で決めることはせず、どの枠を空けるかは人が決めてください。必要なら、詳細設定の必要人員の表で「空きでOK」にできます。
枠ごとの「休業する曜日」「中心の人」「入れる人（優先順）」「昼に清掃をする枠」は、詳細設定の必要人員の表で変えられます。

**必ず守る（ハード制約）**

- 本人が出した希望休（休・特・✖）の日には入れない
- 労働時間の上限（下の「労働条件」）
- 法定休日：毎週1日以上
- 区分ごとの月の休日数（社員8日・PA8日が初期値）
- 連勤は6日まで（7連勤は法定休日に反するため設定不可）
- 対応できるパターン・担当の仕事だけを割り当てる
- 1人1日1枠まで／休館日は全員休み

**できるだけ守る（コスト最小化）**

- 各枠の必要人数を満たす（予約客室数に連動）
- 出勤日数を一人ひとりの目安に近づける
- 連休の希望を、予約の少ない並びに入れる
- 前日と同じパターンを優先する

ランダムな初期値で何通りも試し、いちばん評価値の低い配置を採用します（既定300回）。

## 労働条件

労働時間・休日の上限は **労働基準法（全国共通）** で、沖縄県独自の基準はありません。
「社員は月8日休み」のような休日数は、法律ではなく会社の就業規則のルールです。

| 設定 | 内容 |
|---|---|
| 1か月単位の変形労働時間制（初期値） | 月の合計が「週40時間 × 暦日数 ÷ 7」以内（31日で177.1時間、30日で171.4時間、28日で160時間）。週40時間を超える週があってもよい |
| 週ごとに数える | 暦週ごとに40時間以内。月をまたぐ週は、月内の日数で按分する（3日しかない週は17.1時間） |
| 週の上限時間 | 通常40時間。常時10人未満の接客娯楽業のみ44時間の特例 |
| 役員 | 労働基準法上の労働者に当たらないため、労働時間の上限の対象外 |

変形労働時間制は、就業規則か労使協定で定めている場合に使えます。
定めていない場合は「週ごとに数える」に切り替えてください（人員が同じなら、人が足りない枠が出やすくなります）。

常勤（記号なし）の人は、スタッフ表の「1日の時間」（初期値8時間）で労働時間を数えます。

## みんなに共有する

### Googleスプレッドシートに反映

社員がいつでも最新のシフトを見られるよう、スプレッドシートに書き出します。
スプレッドシート側に連携用スクリプトを入れて、ウェブアプリとして公開します（最初に1回だけ）。

1. シフトを共有したいスプレッドシートを開き、「拡張機能 → Apps Script」
2. 中身を全部消して、[gas/Code.gs](gas/Code.gs) を貼り付ける（ツールの「連携用スクリプトをコピー」でも写せます）
3. 1行目の `KEY` を好きな合言葉に書き換えて保存
4. 「デプロイ → 新しいデプロイ → 種類：ウェブアプリ」。実行ユーザーは「自分」、アクセスできるユーザーは「全員」
5. 表示されたウェブアプリのURLと合言葉を、ツールの「詳細設定 → スプレッドシート連携」に入れて「保存して接続テスト」

反映すると、次のようになります。

- 「2026年10月」のような月ごとのシートが、いちばん左に作られる（同じ月は上書き）
- ツールの保存データが、非表示の `_data` シートに残る
- 別のパソコンでは、上部の「最新を読み込む」で同じデータを引き継げる

スクリプトが触るのは、そのスプレッドシートだけです（`@OnlyCurrentDoc`）。
連携先URLと合言葉は各ブラウザにだけ保存し、スプレッドシートに預ける保存データには含めません。
ツールは `https://script.google.com/macros/s/…/exec` の形のURL以外には送信しません。

### 画像で保存

1か月分のシフト表を、1枚のPNG（約2900×1600）にします。画面のテーマに関係なく明るい配色で描きます。
LINEへの貼り付け用に、クリップボードへのコピーもできます。
